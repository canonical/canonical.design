Follow text alignment rules

{%- endif -%} {%- if slot == "list_item_title_1" -%}

Prose

{%- endif -%} {%- if slot == "list_item_description_1" -%}

When it comes to aligning prose, we follow two rules:

  • Align prose left.
  • Do not force-justify.

They create consistent starting points, avoid uneven gaps and the “river effect”, and make text easier to read, especially for people with dyslexia.

{%- endif -%} {%- if slot == "list_item_title_2" -%}

Numbers

{%- endif -%} {%- if slot == "list_item_description_2" -%}
  • Align numbers by decimal point when decimals are present.
  • Right-align numbers when no decimal point is present.
{%- endif -%} {%- if slot == "list_item_title_3" -%}

Exceptions

{%- endif -%} {%- if slot == "list_item_description_3" -%}
  • In rare cases, single-line labels directly beneath an icon may be centred. Use as last resort.
  • Text labels inside diagrams created with tools that simply do not support left alignment.
{%- endif -%} {%- endcall %} {% set semantic_color_description %}
  • Default to black color for text.
  • Use color primarily for semantic purposes, such as links, states, feedback, and syntax highlighting.
  • Avoid using brand colors decoratively or as routine emphasis in running text.
  • Color may be used for emphasis when it has a clear purpose, meets accessibility requirements, and is not the only cue.
{% endset %}

Emphasise sparingly

{%- endif -%} {%- if slot == "description" -%}

In general, prefer emphasis that arises from structure. Word order and white space will often carry the thought without need for ornament.

Do not use bold, italic, color, or underline as a substitute for correct heading structure. Overusing emphasis dilutes its effectiveness.

When it comes to emphasis, treatments vary slightly by tier:

Documentation

{%- endif -%} {%- if slot == "list_item_description_2" -%}

Do not track text casually

{%- endif -%} {%- if slot == "description" -%}

Lowercase letterforms are engineered with precise optical spacing and negative counter-shapes designed to form recognizable word silhouettes. Adding positive tracking to lowercase copy disrupts this natural visual rhythm, fractures word recognition, and severely degrades readability.

{%- endif -%} {%- if slot == "list_item_title_1" -%}

Implementation rules

{%- endif -%} {%- if slot == "list_item_description_1" -%}
  • Apply tracking exclusively when setting typography in all-caps or small-caps.
  • Use exactly 0.05em (5%) tracking for all small-caps headers to ensure optimal legibility.
  • Do not use negative tracking to force text blocks or paragraph overflows to fit into a tight layout space.

Follow accessibility standards

{%- endif -%} {%- if slot == "description" -%}

Typography must remain readable when users adapt it to their needs. Do not rely on fixed sizes, fixed containers, or color alone. Design and test typography to meet WCAG AA requirements.

{%- endif -%} {%- if slot == "list_item_title_1" -%}

Use relative type sizes

{%- endif -%} {%- if slot == "list_item_description_1" -%}

Set type with relative units so users can resize text through browser or system settings. Text must scale up to 200% without clipping, overlapping, hidden content, or loss of functionality.

{%- endif -%} {%- if slot == "list_item_title_2" -%}

Meet contrast and state requirements

{%- endif -%} {%- if slot == "list_item_description_2" -%}

Text must meet WCAG AA contrast requirements against its background: 4.5:1 for normal text and 3:1 for large text.

Interactive text must also remain distinguishable in each state: default, hover, focus, active, visited, and disabled.

When color is the only cue that distinguishes a link from surrounding text, the link color must have at least 3:1 contrast against the adjacent text, not only against the background.

{%- endif -%} {%- if slot == "list_item_title_3" -%}

Support text spacing overrides

{%- endif -%} {%- if slot == "list_item_description_3" -%}

Interfaces must continue to work when users increase line height, paragraph spacing, letter spacing, or word spacing. Check that text remains visible, controls remain usable, and labels do not collide.

The baseline grid

{%- endif -%} {%- if slot == "description" -%}

The baseline grid is the backbone of the typography system. It gives type a consistent vertical rhythm and keeps text, components, and spacing from drifting apart as layouts grow more complex.

All line heights in the type system are multiples of the baseline unit. This is what lets different text sizes sit in a coherent rhythm instead of each carrying its own private logic.

It is there to make the system dependable. When alignment is systematic, the whole interface reads as better made.

This matters for three reasons:

{%- endif -%} {%- if slot == "list_item_title_1" -%}

Visual consistency

{%- endif -%} {%- if slot == "list_item_description_1" -%}

All elements adhere to an invisible vertical partitioning of space, rather than floating arbitrarily: headings, body text, lists, tables, and UI text all share the same rhythm.

{%- endif -%} {%- if slot == "list_item_title_2" -%}

Scalable precision

{%- endif -%} {%- if slot == "list_item_description_2" -%}

Everything in our design system, from a simple button to complex components and patterns, aligns to the baseline grid. This alignment is especially visible across columns, reinforcing a sense of precision and rigor.

{%- endif -%} {%- if slot == "list_item_title_3" -%}

Accountability

{%- endif -%} {%- if slot == "list_item_description_3" -%}

Misalignment becomes visible quickly, especially across columns. We provide a baseline grid visualization utility (in both Figma and CSS) to highlight any drift from the grid.

{%- endif -%} {%- endcall %} {%- set weight_pairing_description -%}

Heading pairs share a size and use a minimum weight difference of 200 units, with one exception. In Sites and Apps, H5 and H6 share weight 600, which is 200 above body text. Small caps distinguish H5 from H6.

As size increases, weight usually decreases. Larger headings do not need as much weight to hold their place in the hierarchy. Smaller headings often need more. In tiers where emphasis is expressed through weight, use a further 200-unit increase for the emphasized text.

Line-height ratios in our system follow a traditional pattern: most generous at body text size, then progressively tighter as heading sizes increase. We start at or around 1.5 for body text, depending on tier – a ratio that provides optimal readability for sustained reading while maintaining reasonable space efficiency.
